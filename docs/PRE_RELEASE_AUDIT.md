## 3. Blockers and High Findings (Full Detail)

### `TECH-01` — Store-level validation & duplicate-slug errors are silently erased in the editor
- **Severity:** High
- **Location:** `src/pages/CourseEditorPage.tsx:480-516` (`511-514`), `769-793`
- **What's wrong:** Errors returned by `addCourse` / `updateCourse` (e.g., duplicate `slug`, `code` < 2 chars, `title` < 2 chars) are immediately overwritten by the live-validation `useEffect` on the next render, leaving Save silently failing with no visible banner or field error.
- **Evidence or repro:**
  1. Open `/editor/new`, set `URL Slug` to `guide101-quick-start` (or `Course Code` to `"A"`), and click **Save**.
  2. `validateCourseDraft` (`CourseEditorPage.tsx:118-135`) only checks `.trim()` non-emptiness, not min-length or slug uniqueness.
  3. `addCourse` returns `{ ok: false, error: 'A course with slug "guide101-quick-start" already exists.' }` (`useCourseStore.tsx:165-170`), and `handleSave` calls `setErrorMsg(result.error)` (`786`).
  4. Because `errorMsg` is in the `useEffect` dependency array (`516`), the effect runs immediately, sees `!liveMessages.includes(errorMsg)` (`512`), and executes `setErrorMsg(liveValidation.firstErrorMsg)` (`null`, `513`).
- **Suggested fix:** Add min-length (`>= 2` for `code`, `title`, `department`), slug regex (`/^[a-z0-9-]+$/`), and duplicate-slug checks directly into `validateCourseDraft`, and keep store-level errors separate from `validateCourseDraft` messages (clearing only when the offending field changes).
- **Effort:** S

### `TECH-02` — Corrupt `localStorage` catalog wipes all custom courses and deletes IndexedDB files
- **Severity:** High
- **Location:** `src/lib/storage/localRepositories.ts:50-51`, `src/store/useCourseStore.tsx:128-141`, `src/App.tsx:21-30`
- **What's wrong:** A single invalid course or truncated JSON in `college_course_trees_catalog_v2` causes atomic parse failure, overwrites `localStorage` with only the 2 seed courses, and triggers IndexedDB GC to delete all user-uploaded files.
- **Evidence or repro:** `StoredCatalogSchema.safeParse` (`localRepositories.ts:50`) rejects the entire array if any entry fails; `CourseProvider` (`useCourseStore.tsx:128-141`) falls back to `premadeRepository.getAll()` and immediately saves it over `localStorage`; `App.tsx:27` then runs `garbageCollectFiles` with only seed file IDs (`Set` empty), deleting all user uploads from IndexedDB.
- **Suggested fix:** Backup raw non-empty data (`..._corrupt_backup`) before fallback, parse courses individually so one corrupt course does not drop others, surface a recovery banner, and skip automatic IndexedDB GC when catalog parsing failed.
- **Effort:** M

### `TECH-03` — `saveCourses` and `saveProgress` silently swallow `QuotaExceededError`
- **Severity:** High
- **Location:** `src/lib/storage/localRepositories.ts:57-65, 105-118`, `src/pages/CourseEditorPage.tsx:770-792`
- **What's wrong:** Both `saveCourses` and `saveProgress` catch and ignore `localStorage.setItem` errors, causing silent data loss when storage quota is exceeded or restricted.
- **Evidence or repro:** `localRepositories.ts:60-64` and `113-117` have empty `catch {}` blocks; `CourseEditorPage.tsx:770-792` navigates away claiming success even when `localStorage` rejected the write.
- **Suggested fix:** Return `{ ok: true } | { ok: false, error: string }` from persistence writes and surface a visible `role="alert"` warning in `CourseEditorPage` / `CoursePage` if saving fails.
- **Effort:** M

### `TECH-04` — Embedded webpage `<iframe>` combines `allow-scripts` + `allow-same-origin` and permits `http://`
- **Severity:** High
- **Location:** `src/components/viewer/MaterialViewerModal.tsx:119-129, 790-797, 820-831, 846-857`
- **What's wrong:** The external webpage iframe uses `sandbox="allow-scripts allow-same-origin allow-forms allow-popups"`, direct-PDF and cloud/video iframes omit `referrerPolicy="no-referrer"`, and plain `http://` URLs enter the external iframe.
- **Evidence or repro:** `MaterialViewerModal.tsx:849` sets `allow-scripts allow-same-origin`; if a user/imported URL points to the app's own origin, the framed document can strip its own `sandbox` attribute and access `window.parent`, `localStorage`, and IndexedDB. Lines `792-796` and `820-831` omit `referrerPolicy="no-referrer"`. Line `122` allows `http://`, which `embedResolver.ts:386` classifies as `external`, sending `http://` into `<iframe src>` (`847`).
- **Suggested fix:** Remove `allow-same-origin` from the general external `sandbox` (or reject same-origin URLs), add `referrerPolicy="no-referrer"` to external `direct-pdf` and provider iframes, and route `http://` URLs directly to the `"Open in new tab"` fallback card rather than an iframe.
- **Effort:** S

### `TECH-05` — Unsaved-changes guard misses refresh (`beforeunload`), Back/Forward (`popstate`), and `SearchModal`
- **Severity:** High *(overlaps with `UX-05`)*
- **Location:** `src/pages/CourseEditorPage.tsx:333-368`, `src/components/SearchModal.tsx:115-118`
- **What's wrong:** The editor's unsaved-changes prompt only intercepts clicks on `<a href>` links; browser refresh/tab close, browser Back/Forward, and programmatic navigation via `SearchModal` (`Ctrl+K` / `/`) discard edits silently.
- **Evidence or repro:** Repo-wide grep confirms zero `beforeunload`, `popstate`, or `useBlocker` listeners. `CourseEditorPage.tsx:336-367` only attaches a `click` capture listener for `a[href]`; `SearchModal.tsx:115-118` calls `navigate(to)` directly.
- **Suggested fix:** Add a `beforeunload` handler when `isDirty`, and block in-app programmatic/history navigation (via React Router `useBlocker` or shared navigation guard context used by `SearchModal` and `popstate`).
- **Effort:** M

### `UX-01` — No modal or drawer traps `Tab` focus or restores focus on close
- **Severity:** High *(confirms `ISSUES.md` #6)*
- **Location:** `src/components/DrawerShell.tsx:42-71`, `src/components/SearchModal.tsx:125-191`, `src/components/ConfirmDialog.tsx:37-80`, `src/components/ExportCourseDialog.tsx:99-181`, `src/components/editor/ImportCourseDialog.tsx:79-182`, `src/pages/CoursePage.tsx:393-469`, `src/pages/CourseEditorPage.tsx:1431-1484`, `src/components/assessment/AssessmentBuilderModal.tsx:639-1467`, `src/components/assessment/AssessmentRunnerModal.tsx:421-914`, `src/components/viewer/MaterialViewerModal.tsx:898-988`
- **What's wrong:** Opening any modal or drawer leaves focus behind the backdrop (except `SearchModal`), lets `Tab` move into obscured background elements, and fails to restore focus to the opener on close.
- **Evidence or repro:** Verified live in headless Edge CDP: pressed `Enter` on an SVG tree node to open `LessonDrawer`; `document.activeElement` remained on the background `<g>`, and 6 consecutive `Tab` presses cycled across hidden background SVG nodes (`inDialog: false` for all 6 stops). Pressing `Escape` left focus on the last background node.
- **Suggested fix:** Add a shared `useDialogFocus` hook (capturing trigger element on open, focusing the dialog or initial control, wrapping `Tab`/`Shift+Tab` inside `[role="dialog"]`, and restoring focus on close).
- **Effort:** M

- **Severity:** High
- **Location:** `src/components/SearchModal.tsx:33-40`, `src/components/DrawerShell.tsx:23-32`, `src/components/ConfirmDialog.tsx:21-28`, `src/components/ExportCourseDialog.tsx:60-69`, `src/components/editor/ImportCourseDialog.tsx:31-40`, `src/components/viewer/MaterialViewerModal.tsx:385-393`, `src/pages/CoursePage.tsx:99-116`, `src/pages/CourseEditorPage.tsx:1426-1485`

- **Effort:** M

- **SVG Export Duplication (`CLR-04` / `ISSUES.md` #4):** Raw status hex literals duplicated across `ROADMAP_COLORS`, `src/index.css`, `CourseTreeCanvas.tsx`, and `CoursePage.tsx:184-192` (`handleDownloadSvg`), with `.node-highlighted` missing from exports.
- **Design Consequences & Differentiation Rules (Post-Audit Color Decisions):**
  1. *Accent Purple vs. Recommended Purple (same purple family):* Using a single Purple family for primary CTAs (`--cta-bg`), links (`--accent-purple`), focus rings (`--border-focus`), **and** `.recommended-group-box` (`--recommended-*`) prevents hue fragmentation, but creates visual collision risk in `MaterialList` where recommended containers enclose clickable links and resource badges. Differentiate strictly by **form & structural treatment**: Recommended items use a **`1.5px dashed` border** (`--recommended-border`) + ultra-subtle tint (`--recommended-bg`) + `<Star>` `"Recommended"` header (reserved *exclusively* for recommended), whereas CTAs use solid high-contrast `--cta-bg` + `#ffffff` text, links use underlined text, and focus uses `2px` solid `--border-focus` rings.
  2. *Learning Purple vs. Accent / Recommended Purple:* Assigning `Learning` status to the same Purple family creates overlap with accent buttons/links and recommended boxes in `StatusSegmentedControl`, `ChecklistView`, `ChapterDrawer`, and `ProgressStrip`. Differentiate via a **`1px solid` tinted pill** (`--status-learning-bg` + `--status-learning-border`) and **mandatory non-color cues**: `<BookOpen>` icon + `"Learning"` text in UI pills/segmented controls and text underline in SVG tree nodes, alongside `<CheckCircle2>` + `"Done"` (Green) and `<Ban>` + `"Skip"` / `"Skipped"` (Warm Gray).
  3. *Warning Orange vs. Chapter Amber:* Separating warnings, hints, empty-leaf boxes, failed score pills, and flagged question pills onto **Orange** (`--status-warning-*`) eliminates the previous amber-on-amber collision with Chapter `ChN` tags and chapter accents (`--tag-amber-*` / `--accent-amber`).
- **Intentional Exceptions Compatibility Check:**
  - `Navbar.tsx` (`bg-slate-900` `#0f172b`, `"c."` monogram): Dark navy anchors Light warm `#f7f5f0` cleanly and blends into Dark oxford `#0b0f17`. Keeping `+ New Course` blue (`from-blue-600 to-blue-700`, **5.25:1–6.83:1**) + `border-slate-500` (**3.74:1**) works alongside Purple without hue clash (echoing `ROADMAP_COLORS.edgeBlue` `#2b78e4`), though `Q11` asks whether to optionally align it to Purple (`from-purple-700 to-purple-800`, **7.07:1+**).
  - `ROADMAP_COLORS`: `#dad1fd` + `#7c3aed` (**5.70:1** with `#ffffff`) for SVG `learning` nodes already harmonizes with Purple `Learning`; `done` corner badge `#16a34a` -> `#15803d` (**5.02:1**).
  - `RESOURCE_BADGE_STYLES`: All 10 badges pass `>= 4.58:1` on the new Light warm (`#fdfcfa`) and Dark oxford (`#121926`) surfaces once `textbook` Light (`bg-teal-700`, **5.36:1**), `course` Dark (`dark:bg-red-600`, **4.77:1**), and `official` Dark (`dark:bg-blue-600`, **5.25:1**) are fixed (`assignment` Dark `indigo-500` passes at **4.58:1**). Note that `video` (`bg-purple-300` / `dark:bg-purple-400/25`) shares hue with Recommended/Accent purple inside `MaterialList` (`CLR-02`), remaining distinct via compact badge pill shape vs. `1.5px dashed` container and underlined links.

## 8. Not Assessed and Why

- **Non-Chromium browsers & real mobile hardware (Firefox, desktop Safari, iOS Safari, Android Chrome):** Live verification used headless Microsoft Edge (Chromium) with desktop/mobile emulation; physical touch gestures (two-finger pinch-to-zoom), iOS Safari `blob:` PDF iframe rendering, and mobile virtual keyboard viewport shifts (`h-dvh`) were not empirically run.
- **Interactive screen-reader speech output (NVDA / JAWS / VoiceOver):** Evaluated via DOM/ARIA and keyboard focus inspection; no live screen-reader session was run.
- **Large-scale stress benchmark (50 chapters / 500 lessons / multi-MB uploads):** Bottlenecks (`TECH-10`) were identified via static code inspection rather than live React Profiler / IndexedDB quota measurements.
- **Live third-party cloud/media embeds (YouTube, Vimeo, Google Docs, OneDrive, live audio):** Evaluated via `embedResolver.ts` and `MaterialViewerModal.tsx` inspection rather than live authenticated external network embeds.
- **Transitive `node_modules` license audit:** Verified missing root `LICENSE` (`TECH-17`), but did not audit every transitive package license in `node_modules/`.
